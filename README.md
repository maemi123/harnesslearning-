# Harness Learning —— 内循环的最小复现

> 论文：*Harness Learning: Generalizable Test-Time Adaptation*（arXiv [2609.35738](https://arxiv.org/abs/2609.35738)，CMU，预印本，**未开源**）
>
> 这里复现的是它的**内循环**：让一个模型反复读自己考砸的记录，改写自己的解题程序。
> **不改模型权重、不训练、不需要 GPU。**

---

## 结论先说

四组实验，同一套闭环、同一批题、同一个解题模型，**只换「改代码的那个模型」**：

| proposer（改代码的） | 第 0 轮 | 练过的题 | 同题型新题 | 接受 |
|---|---|---|---|---|
| Qwen3.5-4B | 0.333 | 0.333 | 0.311 | 0/8 |
| Qwen3-8B（执行层有 bug） | 0.367 | 0.417 | 0.333 | 1/4 |
| Qwen3-8B（bug 已修） | 0.300 | 0.400 | 0.400 | 1/5 |
| **DeepSeek-V4.1-Flash** | 0.333 | **1.000** | **1.000** | **4/5** |

但换个**没见过的题型**，收益归零：

| 题型 | 什么都不做 | 跑完 5 轮 | 手写解析器（对照尺） |
|---|---|---|---|
| 打折计算 | 0.750 | **0.650**（掉了） | 1.000 |
| 进制转换 | 0.000 | **0.000** | 1.000 |

**一句话：不训练的话，它学会的不是「遇到难题就写代码」，而是「给当前这几类题各写一个解析器」。**

这正好是论文坚持要训练 proposer 的理由——也是这个仓库最想验证的一件事。

完整分析见 [`docs/实验报告.md`](docs/实验报告.md)。

## 这个仓库复现了什么

| 论文里的东西 | 这里做了吗 | 说明 |
|---|---|---|
| 改 harness 的闭环（跑分 → 看错题 → 改码 → 复跑 → 涨了才留） | ✅ 完整 | `loop.py` |
| Base proposer（完全不训练的那条基线） | ✅ 完整 | 论文这一格是 0.282 |
| 开发集 / 保留集切分（防止背答案） | ✅ 完整 | `bench.py` |
| 代码执行沙箱（超时 + 违禁扫描） | ✅ 完整 | `sandbox.py` |
| **SFT + RL 训练 proposer** | ❌ 跳过 | 唯一需要 GPU 的一步，也是本仓库刻意不做的 |
| 21/26 个题族、每题 8 个提案 | ❌ 缩到 3+2 个题族、每题 1 个提案 | 规模小，只能看趋势 |

**跳过训练不算偷工减料**——论文自己设了「完全不训练」的 Base 基线，本仓库跑的就是那一格。

## 快速开始

```bash
# 1) 准备一个 OpenAI 兼容的 key（默认硅基流动，可换）
#    export HL_API_KEY=sk-xxxx      # Windows 用 set HL_API_KEY=sk-xxxx
#    也可以写进 harness_lab/.env：HL_API_KEY=sk-xxxx

# 2) 先离线自检（不联网、不花钱，验证管线通不通）
HL_OFFLINE=1 python -m harness_lab.selftest

# 3) 正式跑 5 轮
python -m harness_lab.loop --rounds 5 --tag myrun
```

产物在 `harness_lab/runs/<时间戳>/`：

- `round_XX_harness.py` —— 每一代 harness 的完整代码（**最值得看的部分**）
- `round_XX_score.json` —— 每道题的题面、模型答的、正确答案
- `summary.json` —— 最终汇总 + token 消耗

想看「换没见过的题型还灵不灵」：

```bash
python -m harness_lab.heldout_family
```

## 一轮循环长什么样

```
第 0 轮    用第 0 层 harness 跑 60 道开发题
            ↓ 把错题的「题目 / 它答的 / 正确答案」整理成报告
proposer   读报告，改写 harness.py（只认完整 Python 文件，200 行以内）
            ↓
第 1 轮    跑同一批开发题 → 分数严格变高才保留，否则回滚
            ↓
          ... 重复 N 轮 ...
            ↓
最终考核   跑 45 道「全程没给它看过」的题 → 这个分数才能对外说
```

`harness_lab/seed_harness.py` 是第 0 层，只有 10 行：

```python
def run(question, ask, py):
    return ask(question)          # 题目直接丢给模型，让它心算
```

`harness_lab/harness.py` 是跑完 5 轮后被改出来的最终版本（200 行），可以对照看它到底加了什么。

## 目录结构

```
harness_lab/
  config.py         所有开关：模型、题族、题量、轮数、并发
  tasks.py          题族生成 + 判分（想换 GIS 题就改这一个文件）
  seed_harness.py   第 0 层，永不修改
  harness.py        跑完 5 轮后的最终产物（示例）
  sandbox.py        子进程执行 + 超时 + 违禁代码扫描
  bench.py          跑分、评分、挑失败样例
  proposer.py       组 prompt、解析代码块、校验
  loop.py           主循环
  selftest.py       离线自检
  heldout_family.py 用两个没参与改进的题型测泛化
controls/           手写解析器，只用来证明「题可解、判分没错」
docs/               实验报告、组会报告
```

## 三个必须知道的局限

1. **这不是论文的完整复现。** 没有 SFT、没有 RL、没有 26 个题族、没有每题 8 个提案。只验证「闭环能不能自己变好」。
2. **沙箱不是真沙箱。** 只挡了最常见的几种破坏（`import os`、`eval`、超时），没做系统级隔离。**别在有重要文件的机器上跑来源不明的 harness。**
3. **样本小。** 5 轮 × 60 题，只能看趋势。同一份 harness 重复跑，分数抖动约 ±0.06（极差 0.117），涨幅小于这个数就当没涨。

## 和论文数字的关系

论文在 **26 个未见题型**上的平均分：

| 配置 | 分数 |
|---|---|
| Base（完全不训练） | 0.282 |
| SFT（看 432 条 35B 老师示范） | 0.415 |
| SFT + RL | 0.528 |
| 35B 老师本人（不训练） | 0.501 |

**本仓库的分数不能直接和这些比。** 题族、题量、模型、命题格式全都不同。

能对上的只有趋势：**不训练 → 只在练过的题型上有效，跨题型收益≈0**。

## 想换成自己的题

只改 `tasks.py` 两个地方：

```python
GENERATORS = {"my_task": _gen_my_task}     # 生成题目
SCORERS    = {"my_task": _score_my_task}   # 判分
```

闭环、沙箱、proposer 一行都不用动。
