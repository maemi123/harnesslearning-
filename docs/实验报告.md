# 小复现实测结果（第 2 版，含强模型对照）

> 2026-11-07｜Windows + Python 3.13｜**全程 0 GPU，只花 API 费**
> 代码在 `harness_lab/`，原始日志在 `harness_lab/runs/`

## 一句话结论

**换一个会写代码的强模型，闭环立刻从「改不动」变成「刷满分」；但这个满分只存在于它练过的那三种题型上——换一种问法，收益归零。**

这就是论文为什么非要训练 proposer：不训练的话，它学到的只是「给当前这几类题各写一个解析器」。

---

## 一、四组实验，一张表看完

同一套闭环、同一批题、同一个解题模型（GLM-4-9B），**只换 proposer**：

| # | proposer（改代码的那个） | 第 0 轮 | 练过的题 | 同题型新题 | 接受 |
|---|---|---|---|---|---|
| 1 | Qwen3.5-4B | 0.333 | 0.333 | 0.311 | 0/8 |
| 2 | Qwen3-8B（执行层有 bug） | 0.367 | 0.417 | 0.333 | 1/4 |
| 3 | Qwen3-8B（bug 已修） | 0.300 | 0.400 | 0.400 | 1/5 |
| 4 | **DeepSeek-V4.1-Flash** | 0.333 | **1.000** | **1.000** | **4/5** |

「练过的题」= 60 道开发题，proposer 能看到错题报告。
「同题型新题」= 45 道保留题，**题目没给它看过，但题型一样**。

前两列数字的差距，就是「proposer 会不会改」的全部差别。

## 二、第 4 组到底发生了什么

5 轮，14.7 分钟，77,596 tokens：

| 轮次 | 分数 | 它干了什么 | 代码行数 |
|---|---|---|---|
| 0 | 0.333 | 起点：题目直接丢给模型，让它心算 | 20 |
| 1 | 0.383 | 试着把算式抠出来，交给代码算 | 57 |
| 2 | **0.733** | 补上正则提取 + 结果清洗 | 80 |
| 3 | **0.983** | 加日期推算（datetime） | 128 |
| 4 | 拒绝 | 想一口气写完，写到 221 行超限 | — |
| 5 | **1.000** | 加一元一次方程求解 | 200 |

**注意这个节奏：一轮攻克一个题型。** 它不是学会了「遇到难题就写代码」这个通用习惯，而是给三个题型各写了一个解析器。

最终代码我逐行看过：**没有任何一处硬编码答案**，全是通用正则。所以 1.000 不是背题背出来的——但它是「针对这三类题面格式」写的。

## 三、关键一击：换一种没见过的题型

我另外造了两个题型，**从头到尾没参与改进**，直接拿最终的 harness 去考：

| 题型 | 第 0 层（什么都不做） | 跑完 5 轮 | 手写解析器（证明题可解） |
|---|---|---|---|
| 打折计算（基线较高） | 0.750 | **0.650** | 1.000 |
| 进制转换（基线为 0） | 0.000 | **0.000** | 1.000 |

两个结果都很说明问题：

**进制转换 0.000 → 0.000**：模型自己完全不会做（12 位数的 13 进制，谁心算得出来），而最终的 harness 也一点忙没帮上。它里面压根没有「遇到不会的就去写代码」这条路。

**打折计算 0.750 → 0.650，反而掉了**：这是**负迁移**。它把打折题硬套进算术模板，算出一个错答案就返回了，连「退回让模型自己答」的兜底都没走到。

**结论：练过的题型 1.000，没见过的题型 0 收益甚至负收益。**

## 四、之前那个「涨了但说不清」的问题，现在有答案了

第一轮实验最尴尬的地方：同一个 harness 一个字不改，连跑 5 次得到

```
0.300 → 0.333 → 0.333 → 0.367 → 0.417
```

跨度 0.117，比当时「涨」的那 0.100 还大。所以那时候说「涨了」是站不住的。

现在回头看，三组数据的性质完全不同：

| 实验 | 涨幅 | 能不能算数 |
|---|---|---|
| 1（4B） | +0.000 | 没涨就是没涨 |
| 2、3（8B） | +0.05 ~ +0.10 | **落在噪声里，不算数** |
| 4（DeepSeek） | **+0.667** | **远超噪声，算数** |

判断标准很简单：**涨幅要明显大于抖动幅度（0.117），才能叫「真的变好」。** 0.667 是它的 5 倍多，这次不用担心。

## 五、顺手挖出的那个 bug（比结论更值钱）

`py()` 一开始的写法是先 `eval` 再 `exec`。看着没问题，实际致命：

> Python 3 里 `print(x)` **本身就是合法表达式**，`eval` 能通过。
> 于是 `eval("print(41777)")` 真的打印了，但**返回 None**——输出被吞掉，harness 拿到字符串 `"None"`。

结果：所有用 `py()` 的候选全被判 0 分，看起来像「proposer 写的全是废代码」，实际是执行层吃掉了结果。

这个 bug 只在模型写 `print(...)` 时触发——而那恰好是最自然的写法。修完之后，同一个 harness 从 0/20 变成 20/20。

## 六、和论文对上了，但要说清楚口径

论文在 **26 个没见过的题型** 上的平均分：

| 配置 | 分数 |
|---|---|
| Base（完全不训练） | 0.282 |
| 只模仿 35B 老师（SFT，432 条示范） | 0.415 |
| 再加 RL | 0.528 |
| 35B 老师本人（不训练） | 0.501 |

**我这次测到的 1.000 不能直接和 0.62 比，因为口径不同。**

- 我的「同题型新题 1.000」≈ 论文里「同一族换新题」，这个数字本来就容易高。
- 我的「没见过的题型 0.000」才对应论文的「unseen families」，这一格我等于没动。

所以准确的对照是：

| | 论文 Base | 我们（DeepSeek，不训练） |
|---|---|---|
| 未见题型上的收益 | 0.282（比 seed 略高） | 0.000（一点没涨） |
| 结论 | 不训练就是不行 | **一致** |

而「换个强模型能到 0.501」这一条也对上了：**模型越强，改得越好，但天花板仍然是「当前题型」，不是「跨题型」。**

## 八、下一步（按性价比排）

1. **把「跨题型」立成正式指标。** 现在只有两个自造题型，样本太小。要多造 4–5 个没见过的题型，才能说「迁移能力 = 0」。
2. **每轮出多个提案再挑**（论文是 8 个）。这次 5 轮里有 1 轮直接废掉（超行数），多采样能救回来。
3. **想要跨题型有收益，就绕不开训练。** 最便宜的路径是「拿强模型的成功修改当示范，SFT 一个小模型」——论文的 432 条就是这么来的。
