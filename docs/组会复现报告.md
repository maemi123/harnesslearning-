# Harness Learning 小规模复现

> 组会汇报 ｜ 2026-11-07
> 复现对象：Harness Learning: Generalizable Test-Time Adaptation（arXiv 2609.35738，CMU，预印本）

## 一句话

论文没有开源，我按它的思路从零搭了一套最小闭环，**只复现内循环（改 harness），不做外循环（训练 proposer）**。四组实验下来结论很干净：

> **换个会写代码的强模型，能在练过的题型上从 0.33 刷到 1.00；但换一种没见过的题型，收益是零，甚至倒退。**

这恰好验证了论文为什么要花算力训练 proposer——不训练学到的不是「怎么写代码」，是「怎么给这几类题写解析器」。

---

## 一、复现的是哪一半

论文把系统分成两个圈（§3 原话：outer loop trains the proposer, inner loop uses the proposer to adapt a harness）：

| 循环 | 干什么 | 要不要训练 | 这次 |
|---|---|---|---|
| **内循环** | 拿一个 proposer，反复「跑题 → 看错题报告 → 改 harness → 再跑」 | 不要 | ✅ **完整做了** |
| **外循环** | 拿「改完涨没涨」当奖励，训练 proposer 本身（SFT + RL） | 要，得用 GPU | ❌ **没做** |

**为什么敢跳过外循环？** 论文自己留了「Base proposer」这条基线——完全不训练，直接拿基座模型来改，在没见过的题型上是 **0.282**。跳过训练不等于偷工减料，等于只跑到这条基线为止。

---

## 二、为什么是「照着搭」，不是「跑通官方代码」

| 查了什么 | 结果 |
|---|---|
| arXiv 页面 | 只有 v1（2026-09-28 上传），无 Comments、无 code 链接、无项目主页 |
| PDF 全文搜 `github` / `code is available` / `release` | **零匹配**，全篇没有一句代码可获取性声明 |
| 关键材料 | 论文自己写明 prompt「not the complete production prompt」 |

**缺的三样硬东西**：完整的 revision prompt、seed harness 源码、432 条 SFT 语料。

**公开的部分**：Qwen 系列权重、Reasoning Gym 基准、GRPO 的现成实现。

所以这次不是「复现别人的仓库」，是「按论文的方法重新实现一遍」。这也决定了规模：**不追论文的 21 个题族，只搭 3 个，把机制跑通。**

---

## 三、搭出来的东西：四件套

| 部件 | 是什么 | 规模 |
|---|---|---|
| **题** | 三个题族：大数混合运算 / 两边带 x 的方程 / 日期推算 | 60 道开发 + 45 道保留 |
| **harness** | 一个 20 行的 Python 文件，只做「题目 → 模型 → 答案」 | 第 0 层 |
| **沙箱** | 子进程执行 + 超时 + 禁 `os/sys/eval/open` | 单题上限 180 秒 |
| **proposer** | 读失败报告 → 输出完整新代码 → 语法检查 → 冒烟测试 → 全量跑分 | 可换模型 |

一轮的流程就是：**跑 60 题 → 把最惨的 6 道错题连同「它答的 / 正确答案」贴给 proposer → 它输出新代码 → 跑 3 题试水 → 跑 60 题全量 → 涨了才留，不涨回滚。**

---

## 四、怎么算分才可信

这是整个实验最容易被质疑的地方，先说清楚：

| 集合 | 谁看得见 | 作用 |
|---|---|---|
| **开发集 60 道** | proposer 看得到错题报告 | 用来改代码、也用来判「涨没涨」 |
| **保留集 45 道** | **全程锁死**，只在最后考一次 | 防背答案。题型相同、题目不同 |
| **两个新题型**（+40 道） | **从头到尾没参与改进** | 考「换一种问法还灵不灵」，对应论文的 unseen families |

判定规则：**每轮改完必须重跑 60 道，分数严格高于当前最好才保留，否则回滚。**

表格里「接受 4/5」就是这个意思：5 轮改动里有 4 轮通过了这道关卡，1 轮被扔掉（第 4 轮写到了 221 行，超过 200 行上限，直接作废）。

---

## 五、主实验：只换 proposer，其他全不变

同一套闭环、同一批题、同一个解题模型（GLM-4-9B），**唯一变量是「谁来改代码」**：

| # | proposer | 第 0 轮 | 练过的题 | 同题型新题 | 接受 | token |
|---|---|---|---|---|---|---|
| 1 | Qwen3.5-4B | 0.333 | 0.333 | 0.311 | 0/8 | 7.4 万 |
| 2 | Qwen3-8B（有 bug） | 0.367 | 0.417 | 0.333 | 1/4 | 12.2 万 |
| 3 | Qwen3-8B（修好 bug） | 0.300 | 0.400 | 0.400 | 1/5 | 13.3 万 |
| 4 | **DeepSeek-V4.1-Flash** | 0.333 | **1.000** | **1.000** | **4/5** | 7.8 万 |

前两组的「涨」其实不算数——同一个 harness 一个字不改连跑 5 次，分数就在 0.300 ~ 0.417 之间抖（极差 0.117）。**涨幅没超过抖动，就不能叫变好。** 第 4 组的 +0.667 是这个抖动的 5 倍多，才站得住。

## 六、第 4 组的五轮，一轮攻克一个题型

| 轮次 | 分数 | 它干了什么 | 代码行数 |
|---|---|---|---|
| 0 | 0.333 | 起点：题目直接丢给模型心算 | 20 |
| 1 | 0.383 | 把算式抠出来，交给代码算 | 57 |
| 2 | **0.733** | 补正则提取 + 结果清洗 | 80 |
| 3 | **0.983** | 加日期推算（datetime） | 128 |
| 4 | 拒绝 | 想一口气写完，221 行超限 | — |
| 5 | **1.000** | 加一元一次方程求解 | 200 |

最终代码逐行看过：**没有一处硬编码答案**，全是通用正则。

**但注意这个节奏：三个题型、三次跳跃。** 它不是在学「遇到难题就写代码」这个通用习惯，是在给三个题型各写一个解析器。

## 七、关键一击：换一种没见过的题型

另外造两个题型，**从没参与改进**，直接拿最终的 harness 去考：

| 题型 | 第 0 层（一行没改） | 跑完 5 轮 | 手写解析器（对照尺） |
|---|---|---|---|
| 打折计算（模型本来就会一半） | 0.750 | **0.650** ↓ | 1.000 |
| 进制转换（模型完全不会） | 0.000 | **0.000** → | 1.000 |

> 第三列不是「另一种方法」，是**校验尺**：手写的都能拿 1.000，说明题能解、判分器没错，那么前两列的低分只能是 harness 的问题。

两个结果：

- **进制转换 0.000 → 0.000**：12 位数的 13 进制，模型心算必错，而强化后的 harness 一点忙没帮上。它里面根本没有「遇到不会的就写代码」这条路。
- **打折题 0.750 → 0.650，反而掉了**：这是**负迁移**。它把打折题硬套进算术模板，算错了还直接返回，连「退回让模型自己答」的兜底都没走到。

**练过的题型 1.000，没见过的题型 0 收益甚至负收益。**

---

## 八、这说明了什么

**第一，瓶颈在 proposer，不在闭环。** 同一套流水线，4B/8B 改 8 轮纹丝不动，DeepSeek 5 轮刷满。所以「方法不行」这个判断是错的，「改代码的那个模型不行」才是对的。

**第二，但「刷满」是假象。** 它学到的是「这个题面长这样，就写这个解析器」。题型一换，解析器全废。这和论文说的「不训练只能做局部拟合」是一回事。

**第三，这正好解释了论文为什么值得花算力。** 论文要的不是「在见过的题上变好」——那太容易了；是「换题型还能变好」。后者只能靠外循环（先看 35B 老师示范，再用 RL 试错）。

论文的对照数据（26 个没见过的题型，平均分）：

| 配置 | 分数 |
|---|---|
| Base（不训练） | 0.282 |
| 只模仿老师（SFT，432 条） | 0.415 |
| 再加 RL | 0.528 |
| 35B 老师本人（不训练） | 0.501 |

我们这次测到的「未见题型 0 收益」，对应的是第一行。

---

## 九、这次证明了什么 / 没证明什么

**证明了（这三条是实的）：**

1. 这套闭环**不需要 GPU**，笔记本 + API 就能跑通全流程（0 元级成本）。
2. **proposer 的能力是决定性变量**：同一套流程，弱模型 0/8 次改对，强模型 4/5 次。
3. 强模型能把「练过的题型」刷满，但**跨题型迁移为零**——而且会**负迁移**，把原来能答对的题弄错。

**没证明：**

1. 论文的 SFT / RL 到底能带来多少提升（没做外循环）。
2. 只有 2 个新题型，样本太小，不足以说「迁移能力严格为 0」。
3. 我们的题面格式固定，比论文的 Reasoning Gym 简单，不能直接和论文的数字对比。

## 十一、下一步

1. **把「跨题型」立成正式指标。** 多造 4–5 个没见过的题型，才能把「迁移能力 = 0」说成结论而不是观察。
2. **每轮多出几个提案再挑**（论文是 8 个）。这次 5 轮里有 1 轮直接废掉，多采样能救回来。
3. **想做外循环，最便宜的路是「拿强模型的成功修改当示范」**——论文那 432 条 SFT 语料就是这么来的，不需要 RL 也能先跑起来。
